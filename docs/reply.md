## 概要

投稿（Post）に対して、ログインユーザーがリプライ（短い返信）を投稿・削除できる機能を追加する。
一覧画面（`posts/index`）の各投稿から「詳細」画面（`posts/show`）に遷移し、そこで投稿本文とリプライ一覧の確認、リプライの投稿・削除を行う。

## 受け入れ条件

- ログインユーザーは、投稿の詳細画面でリプライ本文を入力し、その投稿に対するリプライを投稿できる。
- 投稿の詳細画面には、その投稿に紐づくリプライが一覧表示される（新しい順）。
- リプライは投稿した本人のみが削除できる。他人のリプライを削除しようとした場合は403になる。
- 未ログインユーザーが詳細画面やリプライ投稿・削除にアクセスした場合、既存の投稿一覧などと同様にログイン画面へリダイレクトされる（`auth` ミドルウェア配下）。
- 投稿が削除された場合、その投稿に紐づくリプライも自動的に削除される。
- 投稿一覧画面の各投稿に「詳細」リンクが追加され、詳細画面に遷移できる。

## 変えないもの

- 既存の投稿（Post）の作成・編集・削除の仕様、`PostPolicy`（本人のみ編集・削除可）は変更しない。
- 認証の仕組み（Fortify）、ログイン後のリダイレクト先（`/posts`）は変更しない。
- 既存の4画面（ログイン・登録・一覧・編集）のデザイン（白背景・ヘアライン・中央カラム・円形アバター・ピルボタン）のトーン＆マナーは、新設する詳細画面にもそのまま適用する。
- `usera@example.com` / `userb@example.com` の検証用アカウントのメール・パスワードは変更しない。

## 増えるテーブル

### replies テーブル

| カラム | 型 | 備考 |
| --- | --- | --- |
| id | bigint, PK | |
| post_id | bigint, FK → posts.id | `cascadeOnDelete()`。投稿削除時にリプライも削除される |
| user_id | bigint, FK → users.id | リプライの投稿者 |
| content | text | リプライ本文（140字以内） |
| created_at / updated_at | timestamp | |

- `Post hasMany Reply`、`Reply belongsTo Post`、`Reply belongsTo User`。

## 増える画面

### 投稿詳細画面（`posts/show`、ルート名 `posts.show`、`GET /posts/{post}`）

- 投稿本文（投稿一覧と同様の見た目：アバター・名前・時刻・カテゴリタグ・タイトル・本文）を表示する。
- リプライ投稿フォーム（textarea、140字以内、残り文字数表示）を表示する。
- その投稿に紐づくリプライを新しい順で一覧表示する（投稿者アバター・名前・時刻・本文）。
- 自分が投稿したリプライには「削除」ボタンを表示する（`@can('delete', $reply)`）。
- リプライが0件のときは「まだ返信がありません。」を表示する。

### 既存画面の変更（`posts/index`）

- 各投稿のアクション行に「詳細」リンクを追加し、`posts.show` に遷移できるようにする（既存の編集・削除リンクはそのまま）。

## 入力チェックとメッセージ一覧

リプライ投稿（`POST /posts/{post}/replies`）の `content` について、投稿編集（`title`/`content`）のバリデーションと同じ方針で以下を適用する。

| 項目 | ルール | メッセージ |
| --- | --- | --- |
| content | required | 本文を入力してください。 |
| content | max:140 | 本文は140字以内で入力してください。 |

バリデーション失敗時は詳細画面に戻り、入力済みの内容（`old('content')`）とエラーメッセージを表示する。

## テスト観点

- 投稿詳細画面に投稿本文とその投稿に紐づくリプライが表示される。
- ログインユーザーは有効な本文でリプライを投稿できる（DBに保存され、詳細画面にリダイレクトされる）。
- 本文が空の場合、リプライ投稿は失敗し、バリデーションエラーになる（DBに保存されない）。
- 本文が140字を超える場合、リプライ投稿は失敗し、バリデーションエラーになる（DBに保存されない）。
- リプライの投稿者本人は、自分のリプライを削除できる。
- リプライの投稿者以外のユーザーは、他人のリプライを削除できない（403）。
- `ReplyPolicy::delete` が本人のみ `true` を返すことを単体で検証する。
